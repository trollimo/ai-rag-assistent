# OWASP Top 10: обзор и как использовать

## Что это
OWASP Top 10 — регулярно обновляемый список самых частых и опасных классов
уязвимостей веб-приложений. Не спецификация, а приоритизированный чек-лист:
использовать как основу для code review и порогов в SAST/DAST-сканерах, а
не как исчерпывающий список угроз.

## Категории (редакция 2021, актуальна на 2026)
1. **Broken Access Control** — сломанная авторизация: пользователь получает
   доступ к чужим данным/действиям.
2. **Cryptographic Failures** — слабое шифрование или его отсутствие для
   чувствительных данных (пароли, токены, PII).
3. **Injection** — SQL/NoSQL/OS/LDAP-инъекции, XSS теперь тоже здесь.
4. **Insecure Design** — уязвимость заложена на уровне архитектуры, патчем
   не лечится (нужен redesign).
5. **Security Misconfiguration** — дефолтные пароли, открытые админ-панели,
   verbose-ошибки в проде, лишние включённые фичи.
6. **Vulnerable and Outdated Components** — устаревшие зависимости с
   известными CVE.
7. **Identification and Authentication Failures** — слабые пароли, отсутствие
   rate-limit на логине, небезопасное управление сессиями.
8. **Software and Data Integrity Failures** — доверие непроверенным
   источникам кода/данных (CI/CD supply chain, автообновления без подписи).
9. **Security Logging and Monitoring Failures** — атаку невозможно
   обнаружить постфактум из-за отсутствия логов.
10. **Server-Side Request Forgery (SSRF)** — сервер делает запрос по URL,
    который контролирует атакующий.

## Как применять в разработке
- В PR-чеклист: «затрагивает ли изменение auth/access control? добавлены ли
  новые внешние HTTP-запросы (риск SSRF)? новые зависимости проверены на CVE?»
- В CI — SAST (Semgrep, CodeQL) на инъекции и небезопасные паттерны, SCA
  (Dependency-Check, `npm audit`, `pip-audit`) на уязвимые зависимости.
- Для API — обязательный DAST-скан (OWASP ZAP) перед релизом в прод для
  публичных эндпоинтов.

## Частая ошибка в приоритизации
Команды фокусируются на экзотичных категориях (SSRF) и упускают банальные:
по статистике инцидентов **Broken Access Control** — самая частая причина
реальных утечек, а не сложные крипто-атаки. Начинать ревью стоит с проверки
«кто и как проверяет права на этот эндпоинт», а не с поиска SQL-инъекций.
