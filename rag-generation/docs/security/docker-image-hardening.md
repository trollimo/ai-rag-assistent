# Безопасная сборка Docker-образов

## Базовый образ
```dockerfile
# Плохо — большой, много лишних утилит, потенциальных CVE
FROM ubuntu:latest

# Лучше — минимальный, версия закреплена
FROM python:3.11-slim

# Ещё меньше поверхность атаки — distroless (нет shell, нет package manager)
FROM gcr.io/distroless/python3-debian12
```
`:latest` никогда не использовать в проде — образ под этим тегом меняется
без предупреждения, воспроизводимость сборки теряется. Пиновать версию, а
для критичных случаев — ещё и digest (`python:3.11-slim@sha256:...`).

## Непривилегированный пользователь
Контейнер по умолчанию работает под `root` — если атакующий вырвется из
приложения, у него будут права root внутри контейнера (а при уязвимости в
самом Docker/рантайме — потенциально и на хосте).
```dockerfile
RUN useradd -m -u 1000 appuser
USER appuser
```

## Multi-stage сборка — не тащить в финальный образ лишнее
```dockerfile
FROM node:20 AS builder
WORKDIR /build
COPY . .
RUN npm ci && npm run build

FROM node:20-slim
COPY --from=builder /build/dist /app
# компилятор, dev-зависимости, исходники — остались в builder-стадии,
# в финальном образе их нет
```
Меньше образ = меньше поверхность атаки и быстрее скан на уязвимости.

## Секреты — никогда не в слоях образа
```dockerfile
# Плохо — секрет остаётся в истории слоёв навсегда,
# даже если следующей командой его "удалить"
ARG API_KEY
RUN echo $API_KEY > /app/.key

# Правильно — BuildKit secret mount, не попадает в слой
RUN --mount=type=secret,id=api_key \
    API_KEY=$(cat /run/secrets/api_key) && ./configure.sh
```
```bash
docker build --secret id=api_key,src=./secret.txt .
```
`ARG`/`ENV` со значением секрета виден любому, у кого есть `docker history`
на образ — даже после `RUN rm`, слой с оригинальным значением остаётся в
образе физически.

## Сканирование образа
```bash
trivy image myapp:1.2.3
```
Встраивать в CI как отдельный шаг после сборки, до пуша в registry —
падение на `CRITICAL`/`HIGH` уязвимостях блокирует релиз.

## .dockerignore
Аналог `.gitignore` для контекста сборки — без него `COPY . .` утащит в
образ `.git/`, `.env`, `node_modules/`, тестовые фикстуры с реальными
данными. Минимум:
```
.git
.env
.env.*
node_modules
__pycache__
*.pyc
.venv
```
